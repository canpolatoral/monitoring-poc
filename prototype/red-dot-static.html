Finding the red dot in a fund transfer

A customer's transfer is slow. Every hop below already runs an Envoy sidecar, so the mesh shows exactly which call failed, and four signals confirm why.

How the red dot was found

1

Kiali turns the edge red

The service graph colors each hop by live error rate and latency. One edge stands out.

2

The alert fires

Prometheus sees payments error rate above 5% for two minutes and pages on-call.

3

One trace shows where

In Tempo, 4.1 of 4.3 seconds are spent waiting on core banking. The services in OpenShift are fast.

4

The access log names the cause

Envoy's response flag UT means an upstream timeout, not a bug in payments code.

upstream=core-banking:443
duration=4002ms
flags=UT

Failing hop: payments-svc to core banking VM

Ruled out by the same data: the cluster network, the payments code, and Oracle DB, all green. Routed straight to the core banking team instead of a war room.
